# 09 — Security and observability

## 1. Security controls (`SEC-*`)

### 1.1 Identity and access
- **SEC-IAM-01** (active) Application identity is the pre-existing instance profile only (`CON-IAM-03`). No application code uses long-lived AWS keys. The SDK uses the instance metadata credentials (IMDSv2).
- **SEC-IAM-02** (active) Application-level authorization is enforced by the API (`API-AUTH-*`, `API-DOC-09`, `API-ADM-*`). Roles are `user` and `admin` only.
- **SEC-IAM-03** (active) Operators use AWS Systems Manager Session Manager for shell access. No SSH key pairs are created (`CON-EC2-05`).

### 1.2 Secrets
- **SEC-SEC-01** (active) No secret appears in Git, Terraform outputs, userData logs, application logs, or the frontend.
- **SEC-SEC-02** (active) The RDS master password is generated by Terraform (`random_password`) and stored as SSM Parameter Store `SecureString` at `/docuprocess/sandbox/db/password` (`INF-RDS-06`). Instances read it at boot with `aws ssm get-parameter --with-decryption`. Verified 2026-11-03: the instance role may call `ssm:GetParameter` (`ADR-033`).
- **SEC-SEC-03** (active) Terraform state contains the generated password. State is local, git-ignored, and never shared (`INF-STATE-01`).


### 1.3 Data protection
- **SEC-DATA-01** (active) Data at rest: S3 with SSE-S3, DynamoDB with the default AWS-owned encryption, RDS storage encryption is NOT enabled, because the default RDS encryption key is a KMS key and the sandbox has KMS list access only (`CON-KMS-01`). Decision `ADR-032` records this. EBS root volumes are encrypted (`INF-EC2-02`).
- **SEC-DATA-02** (active) Data in transit: browser to CloudFront is HTTPS (`INF-CDN-02`). CloudFront to ALB is HTTP inside AWS (`SEC-NET-03`). Application to RDS, DynamoDB, S3, and SNS uses TLS through the AWS SDK and explicit MySQL TLS verification against the AWS RDS CA bundle (ADR-037).
- **SEC-DATA-03** (active) Uploaded files are not public. Downloads are not offered in v1; the API never exposes S3 URLs.

### 1.4 Passwords and sessions
- **SEC-AUTH-01** (active) Argon2id password hashing (`API-AUTH-03`, `ADR-021`).
- **SEC-AUTH-02** (active) Session tokens: 256 bits from `secrets`, stored as SHA-256 hash, 8-hour expiry, revocable on logout (`API-AUTH-05/06/08`).
- **SEC-AUTH-03** (active) Login failure responses are identical for unknown email and wrong password (`API-AUTH-04`).

### 1.5 Network
- **SEC-NET-01** (active) Security groups follow `INF-SG-*`. No `0.0.0.0/0` ingress except ALB port 80.
- **SEC-NET-02** (active) The database is in private DB subnets, not publicly accessible, reachable only from `app-sg`.
- **SEC-NET-03** (active) Known limitation: ALB listens on HTTP only (`CON-DNS-02`). Mitigation: the ALB is reachable only through CloudFront in normal use; the ALB DNS name is not advertised to users. Ideally the ALB security group would accept only CloudFront's managed prefix list; this is **not** implemented in v1 and is recorded as an accepted risk in `docs/`.
- **SEC-NET-04** (active) Outbound traffic from private subnets goes through the NAT gateway (`ADR-005`) or the S3/DynamoDB gateway endpoints.

### 1.6 Input handling
- **SEC-IN-01** (active) Uploaded files are validated by content sniffing and size before storage (`API-DOC-02/03`, `ENG-VAL-*`).
- **SEC-IN-02** (active) Filenames are sanitized before use in S3 keys (`API-DOC-05`).
- **SEC-IN-03** (active) SQL is always parameterized (SQLAlchemy Core or ORM). No string-built SQL.
- **SEC-IN-04** (active) Frontend renders dynamic text with `textContent` only (`FE-SEC-01`) and sends a CSP (`FE-SEC-02`).

### 1.7 Logging and privacy
- **SEC-LOG-01** (active) Application logs are structured key=value, one line per event, to stdout (captured by systemd journal).
- **SEC-LOG-02** (active) Logs MUST NOT contain: receipt content, raw OCR text, extracted amounts, NIT, merchant names, customer data, emails, passwords, tokens, S3 keys, or file names. Allowed: IDs (`document_id`, `job_id`, `user_id`), status codes, error codes, counts, durations.
- **SEC-LOG-03** (active) A test captures logs from API and worker flows with sensitive fixtures and asserts none of the sensitive values appear (`TST-SEC-01`).
- **SEC-LOG-04** (active) CloudTrail records AWS API activity (`INF-AUD-*`). It is not a substitute for application logs.

### 1.8 Dependencies
- **SEC-DEP-01** (active) Python dependencies are pinned in `pyproject.toml` with exact versions in a lock file (`uv.lock` or `requirements.lock`). Versions are upgraded deliberately.
- **SEC-DEP-02** (active) Terraform provider versions are locked in `.terraform.lock.hcl`.

## 2. Observability (`OBS-*`)

- **OBS-LOG-01** (active) systemd journal is the log sink for API and worker. CloudWatch Logs agent is out of scope in v1 (decided; logs go to the systemd journal).
- **OBS-MET-01** (active) Metrics are the CloudWatch metrics from `INF-MON-01` and `INF-MON-02`. No custom metrics are required in v1. The worker MAY emit a custom metric `JobsFailed` to the `DocuProcess/Worker` namespace via `PutMetricData` if the sandbox allows it; if not, the job table is the source of truth.
- **OBS-ALM-01** (active) Every alarm in `INF-MON-01` has an action to the `ops-alarms` SNS topic (`INF-SNS-02`) and an OK action where applicable.
- **OBS-HEALTH-01** (active) The API health endpoint (`API-OPS-01`) is the ALB health check. It exposes no version or config.
- **OBS-RUN-01** (active) The runbook in `docs/` lists how to find: API logs (`journalctl -u docuprocess-api`), worker logs (`journalctl -u docuprocess-worker`), a job's state (DynamoDB console, `jobs` table, `job_id`), and the ASG's instance list.
- **OBS-TRACE-01** (active) Every API request and worker job logs the same `document_id` so that an upload can be followed across both processes.

## 3. Documented exceptions and accepted risks

| ID | Exception | Reason | Where recorded |
|---|---|---|---|
| `SEC-NET-03` | ALB HTTP only, no TLS to the ALB | No custom domain or certificate in sandbox | `docs/` risk section |
| `SEC-DATA-01` | RDS storage not encrypted | Gp2 Single-AZ sandbox; not required by the brief | `ADR-032` |
| `SEC-DEP-*` | No automatic dependency updates | Reproducibility | `docs/` |

## 4. Acceptance

- **SEC-ACC-01** (active) `scripts/check_secrets.sh` (or `gitleaks` if installed) finds no secrets in the repository. (`TST-SEC-02`)
- **SEC-ACC-02** (active) The `docs/` risk section lists every row of section 3.
