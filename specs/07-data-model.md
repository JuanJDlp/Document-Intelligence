# 07 — Data model

Two stores, with a clear split of responsibility (`ADR-010`, rationale for the RDS vs DynamoDB choice in `docs/`):

- **RDS MySQL** — identity and access: users, sessions, roles. Relational, transactional, uniqueness constraints.
- **DynamoDB** — document lifecycle: document metadata, processing job state, extraction results. Key-value access, high write rate per document, flexible result shape.

No document-processing data lives in RDS. No user credentials live in DynamoDB.

## 1. RDS MySQL (`DAT-RDB-*`)

### 1.1 General
- **DAT-RDB-01** (active) Engine MySQL 8.0, charset `utf8mb4`, collation `utf8mb4_0900_ai_ci`, storage engine InnoDB. All timestamps are `DATETIME(6)` in UTC.
- **DAT-RDB-02** (active) Primary keys are `CHAR(36)` UUID v4 strings generated by the application.
- **DAT-RDB-03** (active) Session tokens are stored only as `token_hash CHAR(64)` = lowercase hex of SHA-256 of the token.
- **DAT-RDB-04** (active) Schema changes are applied by versioned SQL files in `app/api/src/api/migrations/` named `NNNN_description.sql`. The migration runner records applied versions in `schema_migrations`. The runner takes `GET_LOCK('docuprocess_migrations', 60)` before applying and releases it after.
- **DAT-RDB-05** (active) Migrations are forward-only. No down-migrations in version 1.

### 1.2 Tables

```sql
-- 0001_init.sql

CREATE TABLE users (
  id            CHAR(36)     NOT NULL,
  email         VARCHAR(254) NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  full_name     VARCHAR(200) NOT NULL,
  role          ENUM('user','admin') NOT NULL DEFAULT 'user',
  created_at    DATETIME(6)  NOT NULL,
  updated_at    DATETIME(6)  NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_users_email (email),
  KEY ix_users_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE sessions (
  id           CHAR(36)    NOT NULL,
  user_id      CHAR(36)    NOT NULL,
  token_hash   CHAR(64)    NOT NULL,
  created_at   DATETIME(6) NOT NULL,
  expires_at   DATETIME(6) NOT NULL,
  revoked_at   DATETIME(6) NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_sessions_token_hash (token_hash),
  KEY ix_sessions_user_id (user_id),
  KEY ix_sessions_expires_at (expires_at),
  CONSTRAINT fk_sessions_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE schema_migrations (
  version    VARCHAR(64) NOT NULL,
  applied_at DATETIME(6) NOT NULL,
  PRIMARY KEY (version)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- **DAT-RDB-06** (active) The schema above is the complete version 1 schema. Any column added later requires a new migration file and a `D-` entry if it changes a contract.
- **DAT-RDB-07** (active) A session is valid when `revoked_at IS NULL AND expires_at > now (UTC)`. Both conditions are checked on every authenticated request.
- **DAT-RDB-08** (active) Expired sessions are not purged in v1. They are harmless and small.
- **DAT-RDB-09** (active) The API uses one connection pool per process with `pool_size=5`, `pool_pre_ping=True`, and `pool_recycle=1800`.

### 1.3 Queries that must be supported
- Lookup user by email (unique index).
- Lookup session by token hash (unique index).
- List users with keyset pagination on `(created_at, id)` for `API-ADM-01`. The index `ix_users_created_at` is sufficient for v1 volumes.

## 2. DynamoDB table `documents` (`DAT-DDB-*`)

Table name: `docuprocess-sandbox-documents`. Billing `PAY_PER_REQUEST`.

### 2.1 Keys and indexes
- **DAT-DDB-01** (active) Partition key `document_id` (S).
- **DAT-DDB-02** (active) GSI `gsi_user_created`: partition key `user_id` (S), sort key `created_at` (S). Used to list one user's documents newest first (`ScanIndexForward=false`). Projection: `ALL`.

### 2.2 Item attributes

| Attribute | Type | Set by | Notes |
|---|---|---|---|
| `document_id` | S | API | UUID v4 |
| `user_id` | S | API | Owner |
| `filename` | S | API | Original filename, sanitized copy used for display only (`API-DOC-05`) |
| `mime_type` | S | API | Sniffed type |
| `size_bytes` | N | API | |
| `s3_key` | S | API | Internal. **Never returned by the API** (`API-DOC-10`) |
| `job_id` | S | API | The job that processes this document |
| `processing_status` | S | API, worker | `PENDING`, `RUNNING`, `COMPLETED`, `PARTIAL`, `FAILED` (mirror of the job, `WRK-PER-03`) |
| `processing_attempts` | N | worker | Mirror of the job attempts |
| `processing_last_error_code` | S | worker | Nullable; absent when no error |
| `processing_updated_at` | S | worker | Mirror of the job `updated_at` |
| `result` | M | worker | Engine result without `raw_text`, `WRK-PER-04` limit 100 KB |
| `created_at` | S | API | ISO 8601 UTC with `Z` |
| `updated_at` | S | API, worker | ISO 8601 UTC with `Z` |

- **DAT-DDB-03** (active) Timestamp strings use the fixed format `YYYY-MM-DDTHH:MM:SS.mmmZ` (milliseconds, always 3 digits, always `Z`). Fixed width is required so that string sorting equals chronological sorting.
- **DAT-DDB-04** (active) `result` is absent until the job is terminal.

## 3. DynamoDB table `jobs` (`DAT-DDB-*`)

Table name: `docuprocess-sandbox-jobs`. Billing `PAY_PER_REQUEST`.

### 3.1 Keys and indexes
- **DAT-DDB-05** (active) Partition key `job_id` (S).
- **DAT-DDB-06** (active) GSI `gsi_status_available`: partition key `status` (S), sort key `available_at` (S). Used by the worker's claim query (`WRK-CLM-01`). Projection: `ALL`.

### 3.2 Item attributes

| Attribute | Type | Notes |
|---|---|---|
| `job_id` | S | UUID v4 |
| `document_id` | S | |
| `status` | S | `PENDING`, `RUNNING`, `COMPLETED`, `PARTIAL`, `FAILED` (`WRK-STM-01`) |
| `available_at` | S | Fixed-format timestamp (`DAT-DDB-03`). When the job becomes claimable. For `RUNNING` it is the lease expiry. |
| `attempts` | N | Incremented on each claim |
| `max_attempts` | N | Default `3` (`WRK-CLM-06`) |
| `lease_owner` | S | Worker ID while `RUNNING`; removed when terminal |
| `claimed_at` | S | |
| `last_error_code` | S | Nullable |
| `notification_status` | S | `SENT`, `FAILED`, or absent (`WRK-NOT-03/04`) |
| `notified_at` | S | Present when `SENT` |
| `created_at` | S | |
| `updated_at` | S | |

- **DAT-DDB-07** (active) Every job item MUST have `status` and `available_at` set, because the GSI keys are these attributes. Items without them are invisible to the worker.
- **DAT-DDB-08** (active) Terminal jobs keep their items. They are not deleted in v1.

## 4. Consistency and access rules

- **DAT-ACC-01** (active) The API creates the `documents` item and the `jobs` item in that order, with the S3 object written first. If the job write fails, the document item is deleted and the S3 object is deleted (compensation, `API-DOC-06`).
- **DAT-ACC-02** (active) Job and document transitions are atomic DynamoDB transactions. The job condition fences stale workers by observed status, attempts, available_at and lease_owner (ADR-036).
- **DAT-ACC-03** (active) Strongly consistent reads are used for `GET /api/v1/documents/{id}` (`ConsistentRead=True`) so that a client sees its own upload.
- **DAT-ACC-04** (active) The admin listing (`API-DOC-07` with admin scope and no `user_id`) uses `Scan` with pagination. This is acceptable only for the sandbox volume and MUST be documented in the runbook.
- **DAT-ACC-05** (active) Sensitive values (password hashes, session tokens, S3 keys) are never written to DynamoDB except `s3_key`, which is internal.

## 5. Sizing

- **DAT-SIZE-01** (active) A `documents` item is expected under 110 KB. A `jobs` item is under 2 KB. DynamoDB's item limit is 400 KB.

## 6. Acceptance

- **DAT-ACC-06** (active) A migration test applies `0001_init.sql` to an empty MySQL (or SQLite in unit tests with equivalent types) and checks the constraints listed above.
- **DAT-ACC-07** (active) A worker test verifies that a `jobs` item without `status` or `available_at` is never returned by the claim query (using `moto`).
